# Feishu (Lark) Bitable, also called Lark Base: writing records from a Shortcut

The **verified simplest path** for BYO-DB writes to a Feishu Base = PersonalBaseToken (the Bitable authorization code); no app_secret / tenant token / OAuth (sidesteps C-14, no built-in OAuth, in `${CLAUDE_PLUGIN_ROOT}/docs/apple_shortcuts_dev_protocol.md` §2.1).

**Authentication (permanently valid, zero token dance)**:
- In the Base web UI → top right 「插件」 [Plugins] → 「自定义插件」 [Custom plugins] → 「获取授权码」 [Get authorization code] → copy a `pt-...` string (**permanently valid**, generated by the owner, bound to a single base, do not make it public)
- **Domain = `base-api.feishu.cn`** (⚠️ separately deployed, **not** `open.feishu.cn`); API paths/body are exactly the same as the Feishu Open Platform bitable API
- Header: `Authorization: Bearer pt-...` (**the `Bearer ` prefix is required**) + `Content-Type: application/json`

**Write-record body (PUT update / POST create) = `{"fields":{"field name":value}}`**:
- Outer key **`fields` (plural!)** — missing the s = `code 99992402 "fields is required"`
- For a number field the body kind must be **number** (not テキスト) — otherwise `code 1254061 NumberFieldConvFail`
- Writing a nonexistent option to a single-select field → **auto-adds the option** (tested, zero maintenance); a link field's value = a `["rec_xxx"]` array (complex, can be changed to single-select/text to avoid it)

**Three hard Shortcut pitfalls (tested, must obey)**: ① missing the `Bearer ` prefix = `code 9499 Bad Request` (**not** an auth error code, which is confusing) ② the body's outer `fields` must be plural (**NL "Describe a change" keeps flattening nested fields / changing them to singular** → don't use NL for complex body changes, edit manually) ③ number field kind = number.

**A `datetime` field accepts only epoch milliseconds (four-value test, raw HTTP)**:

| Value sent to a `datetime` field | Result |
|---|---|
| `"YYYY-MM-DD"` | ❌ |
| `"YYYY-MM-DD HH:mm:ss"` | ❌ |
| `"YYYY-MM-DDTHH:mm:ss.000+08:00"` | ❌ |
| epoch milliseconds, e.g. `1788537600000` (a **number**, not a string) | ✅ stored as that instant |

- The **value kind of that cell in the POST body must be number** (`WFItemType: 3`); text is rejected — the same discipline as the "number field kind = number" rule above; datetime follows it too.
- **How to compute milliseconds in a Shortcut**: `日付(1970-01-01)` → `gettimebetweendates` (`WFTimeUntilUnit: Seconds`) → `math ×1000` → `setvariable`, four actions. **Clone an existing chain in the corpus as a whole**, don't assemble the parameters yourself.
- 🚩 **A Lark Base reference doc says "datetime accepts `YYYY-MM-DD HH:mm:ss`" — that sentence applies only to the `lark-cli +record-upsert` wrapper** (it normalizes before sending). A Shortcut goes through raw HTTP, which doesn't accept it. **Before citing any doc on "what value a field accepts", first ask which path it governs.**
- ⚠️ Time zone: with the phone in JST, if the Base's time zone is `Asia/Shanghai` there is a 1-hour difference — the date picker returns local 00:00, which after conversion to an absolute instant may land on 23:00 of the previous day. **Go by testing, don't guess**: after the change, check the stored date immediately after the first real-device entry.

**Dynamic dropdown (pull options live from a Base table; new records need zero maintenance)**: GET the target table's records (Bearer) → 「テキストと一致」 with the regex `(?<="field name":")[^"]+` to extract all values → 「リストから選択」 → variable. New records added to that table → the dropdown picks them up automatically. ⚠️ Don't get the GET's **table id** wrong (e.g. an account dropdown reads the account table, not the ledger table; pointing it at the wrong table gives an empty list).

**Instruction discipline (when building a Shortcut for a non-engineer owner)**: for each body field always give 「キー | kind (テキスト/数字) | which variable the value comes from」 + say explicitly **at which position** to add it; otherwise it defaults to text and errors (the root cause of NumberFieldConvFail).
